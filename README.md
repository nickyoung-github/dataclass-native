# dataclass-native

Use Python dataclasses as a data description language. From them, generate matching C++ structs (and later Rust),
whose storage the Python classes use directly. Native serialisation (msgpack, Arrow/Parquet) is planned.

**Status:** early. Schema introspection, C++ header generation and the native Python binding work. Serialisation
and Rust are to come: see [DESIGN.md](DESIGN.md).

## Defining a schema

```python
import datetime as dt
from collections.abc import Mapping
from dataclasses import dataclass
from enum import Enum, auto

from dataclass_native import DiscriminatedUnion, Int32, Shared, native


class Currency(Enum):
    USD = auto()
    EUR = auto()


@native
@dataclass(frozen=True)
class Money:
    amount: float
    currency: Currency = Currency.USD


@native(tag="party.v1")  # Names the type when serialised
@dataclass(frozen=True)
class Party:
    name: str
    rating: Int32 = 0


@native
@dataclass(frozen=True)
class Cash:
    money: Money


@native
@dataclass(frozen=True)
class Bond:
    isin: str


@native
@dataclass(frozen=True)
class Trade:
    id: int
    instrument: DiscriminatedUnion[Cash, Bond]   # Two structs: needs a tag when serialised
    counterparty: Shared[Party]                  # Shared, not copied; serialised by reference
    tags: tuple[str, ...] = ()
    limits: Mapping[Currency, float] | None = None
    executed: dt.datetime | None = None
```

Classes must be frozen. Containers are `tuple[T, ...]`, `tuple[A, B]`, `frozenset[T]` and `Mapping[K, V]`.

A class may also be a pydantic dataclass (`pydantic.dataclasses.dataclass(frozen=True)`), to validate and convert
what its objects are made from. pydantic's `BaseModel` is not supported.

## Generating C++

```shell
dataclass-native generate cpp --package my_schemas --out generated/include
dataclass-native include-dir   # dataclass_native's own headers, which the generated headers include
```

This writes a header per module (`my_schemas/trades.hpp`, namespace `my_schemas::trades`) of plain C++20 structs,
with no dependency on Python:

```cpp
struct Trade
{
    std::int64_t id{};
    std::variant<Cash, Bond> instrument{};
    dataclass_native::Shared<Party> counterparty{};
    std::vector<std::string> tags = std::vector<std::string>{};
    std::optional<std::map<Currency, double>> limits = std::nullopt;
    std::optional<dataclass_native::DateTime> executed = std::nullopt;

    bool operator==(const Trade&) const = default;
};
```

Unchanged files are left alone, so builds don't rerun needlessly.

## Storing Python objects in the structs

Each schema module `my_schemas.trades` has an extension module, `my_schemas._trades_native`, generated by
`dataclass-native generate nanobind` and built with [nanobind](https://nanobind.readthedocs.io). With CMake:

```cmake
cmake_minimum_required(VERSION 3.25)
project(my_schemas LANGUAGES CXX)

find_package(Python REQUIRED COMPONENTS Interpreter Development.Module)

execute_process(
  COMMAND "${Python_EXECUTABLE}" -m nanobind --cmake_dir
  OUTPUT_STRIP_TRAILING_WHITESPACE OUTPUT_VARIABLE nanobind_ROOT)
find_package(nanobind CONFIG REQUIRED)

execute_process(
  COMMAND "${Python_EXECUTABLE}" -m dataclass_native cmake-dir
  OUTPUT_STRIP_TRAILING_WHITESPACE OUTPUT_VARIABLE dataclass_native_ROOT)
find_package(dataclass_native CONFIG REQUIRED)

# Generates the C++ and adds an extension for each schema module of the package, installed alongside it
dataclass_native_add_extensions(PACKAGES my_schemas PYTHONPATH "${CMAKE_SOURCE_DIR}/src")
```

The extensions are installed to their packages' directories, as a build backend such as scikit-build-core expects.
To use them in place instead, add `LIBRARY_DIRECTORY "${CMAKE_SOURCE_DIR}/src"`.

A class is then bound to its struct when first instantiated. Nothing else changes: it is still the dataclass you
wrote, to type checkers and to `dataclasses`.

```python
party = Party("Acme")
trade = Trade(id=1, instrument=Cash(Money(100.0)), counterparty=party)

trade.instrument.money.amount   # 100.0, read from the C++ struct
trade.counterparty is party     # True: shared, not copied
vars(trade)                     # {'__native__': <my_schemas._trades_native.Trade object>}
Trade(id="1", ...)              # TypeError: Trade.id cannot be '1'
```

## Modes

`DATACLASS_NATIVE_MODE` is one of:

- `strict` (the default): fields are stored in the native structs, and a class whose binding is missing raises.
- `mixed`: as `strict`, but a class whose binding is missing behaves as a plain dataclass.
- `pure`: `@native` returns every class unchanged, as a plain dataclass, for testing.

A binding built from another version of its class raises in `strict` and `mixed` modes: build it again.
